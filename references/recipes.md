## 1. 产品 / 发布片

- **缺省规格**：1080×1080（X）或 1080×1920（抖音、视频号），15–30s，DOM + SVG，可加 GSAP。
- **结构**（15 秒版）：
  - 0–2s：钩子，一个痛点画面或一个问题。
  - 2–7s：产品的一个核心动作，演示它，不要列举。
  - 7–12s：2–3 个能力。每个能力从上一镜的物体长出来。
  - 12–15s：品牌落版，结尾静止 1 秒。
- **视觉主意示例**：一个常驻元素串起全片，比如一张小票、一个播放器、一个光标。
- **关键规则**：
  - 先读真实来源（官网、文档、截图）。
  - 写明"不许编造功能、指标、客户名，不许把测试版说成正式版"。
  - 界面用代码重画成简化版，比贴截图干净。
  - 光标瞄准目标"将要到达"的位置，点击会触发下一拍。
- **常见坑**：
  - 想展示所有功能，结果变成幻灯片。
  - 样机来回旋转。
  - 编造用户数。
- **参考**：daniel-haida-636937、twoclipping-551116、brainextends-606193、howdevelop-733090

## 2. Logo 演绎 / 片头片尾

- **缺省规格**：1080×1080 或 1920×1080，4–8s，SVG。
- **结构**（6 秒版，品牌名 3 秒内必须看清）：
  - 0–0.8s：一个基本形状（点、线、圆、光标）出现。
  - 0.8–2.2s：变形或组装成 Logo；落版前蓄力 0.3–0.5s。
  - 2.0–3.0s：字标按字母从遮罩线下升起，到 3.0s 完全可读。
  - 3.0–5.0s：副标或 slogan 进入，主体缓推。
  - 最后 1s：静止。
- **视觉主意示例**：Logo 里的某个笔画就是开场那条线；全片发生在字标的句点里。
- **关键规则**：
  - 只有一个英雄动作。
  - 落版用临界阻尼弹簧（不过冲）；想要一点弹性就用欠阻尼，过冲不超过约 2%。
  - 片头要短，3 秒内必须看清品牌名。
  - **声音标识必做**：一记音效或 2–6 秒的短乐句，卡在落版那一帧。用户没给，就用 Python 或 Web Audio 合成一个占位，交付时说明可替换。
- **常见坑**：
  - 堆粒子和光效；Logo 被变形到失真；节奏拖沓。
  - **撞脸知名品牌**：深底、单一强调色、一词一框这类缺省搭配，很容易拼出某个大品牌的 Logo。出静帧时把落版帧单独当 Logo 看一遍。
- **参考**：twoclipping-747965、mounnna-497266

## 3. 动态字体 / 金句

- **缺省规格**：1080×1920 或 1080×1080，8–20s，DOM（或 Canvas 做特殊排版）。
- **结构**：按短语分节拍，每个短语一个排版动作。最后一句回到开场构图，收尾。
- **视觉主意示例**：词承担建筑结构，比如"支撑"这个词真的托住上面一行；文字沿轨道运动。
- **关键规则**：
  - 按语义短语编舞，不按单字。
  - 同一时间屏上只有一层文字。
  - 文字作为一个整体设计物移动，不要每个词各自乱跳。
  - 重点词用字重和尺寸区分，不靠颜色堆砌。
- **常见坑**：每个字一个特效；字号太小；停留太短读不完。
- **参考**：gdgtify-929495、gdgtify-130294、gdgtify-989608

## 4. UI 形变循环

- **缺省规格**：1080×1080，8–15s 无缝循环，SVG 或 DOM。
- **结构**：一个形状从不切断，依次变成 8–12 个 UI 状态（按钮 → 加载 → 播放器 → 滑块 → 开关 → 标签页 → 图表 → 通知），最后变回开场形状。
- **关键规则**：
  - 形变靠改尺寸、圆角、颜色完成，不做路径插值乱飞。
  - 容器先变形，内容后进入；下一次变形前，内容先退出。
  - 开关、指示器的前后两条边用不同的弹簧，前沿先走，看起来有拉伸感。
  - 末帧必须等于首帧（`--check` 会报告首尾是否一致）。
- **常见坑**：内容和容器同时动，糊成一团；首尾跳帧。
- **参考**：twoclipping-402193、flxrnc-251921

## 5. 炫技 showreel

- **缺省规格**：1080×1080，10–20s。
- **结构**：一个概念升级三次，例如铅笔线 → 墨水线 → 光线。每次升级时手法也升级。
- **关键规则**：
  - 合集里约 60 条"go all out"一句话 prompt 基本都是抽奖。先把它改写成"一个概念 + 三个升级节点 + 逐拍事件"。
  - 镜头二选一：完全锁定（物体自己动），或者只允许约 1.08 倍的缓推。
- **常见坑**：技巧清单式堆砌；没有主线。
- **参考**：heyiamnick-119558、notdwd-998633

## 6. 概念科普 / 讲解

- **缺省规格**：1920×1080 或 1080×1920，30–90s，SVG + DOM。
- **结构**：
  - 开头抛出一个核心问题，制造好奇缺口。
  - 先给直觉或生活类比，再讲机制。
  - 给一个反直觉点。
  - 一句话结论。
- **关键规则**：
  - 一镜一个关键词配一幅线稿。
  - 隐喻用画面里本来就有的元素表现，不另画插图。
  - 能模拟就真模拟，比如随机游走就让它真的随机游走（用种子随机）。
  - 数字用真实值并标出处，计数器停在真实值上；尺度对比要有参照物。
  - 关键句后画面完全静止至少 0.4 秒。
- **常见坑**：信息塞太满；编数字；装饰性的假 HUD。
- **参考**：astrothewizard-618782、gdgtify-393073、verbove-268381、本 skill 的 assets/template.html

## 7. 配音驱动竖屏短视频（讲史、知识）

- **缺省规格**：1080×1920，30fps，时长跟配音走，SVG + DOM。
- **结构**：一句话一个视觉事件。时间轴来自 build_cues.py 生成的 cues.json。
- **关键规则**：
  - 先有配音，后有动画。动作挂在每句开始的时间点上，转场放在句间停顿里。
  - 底部固定字幕区，画面中上部放当句的一个大字关键词。
  - 用户只给部分句子标了关键词时，没标的句子不要硬造关键词，也不要让关键词区空着：把画面主体（地图、线稿）放大到这块，或者把常驻 HUD（如年份）放大进来。
  - 常驻 HUD 给观众位置感：朝代、年份、地图，按题材选。
- **讲史视觉系统**：
  - 印章、卷轴、竖排朝代名（放左侧，右侧有平台按钮）、年份计数。
  - 势力消长用色块地图表现。
  - 人物用名牌加线稿器物，不画真实人物面孔。
- **常见坑**：画面跟不上话；字幕和关键词重复成两遍同样的字；关键信息被平台界面挡住。
- **细节**：见 voiceover.md。
- **参考**：dotey-927166、stokebuilder-356793、tetsu-tetsu333-576886、henrygsing-050247

## 8. 数据故事

- **缺省规格**：1080×1920 或 1920×1080，15–45s。
- **结构**：一个数字 → 一个人人懂的尺度参照 → 对比 → 一句结论。
- **关键规则**：
  - 跨好几个数量级的数据用对数标尺，但最后的对比要回到线性，让观众看清真实差距（样片里"多出 14%"就是这样处理的）。
  - 数字滚动用等宽数字，只在运动中滚，落定要干脆。
  - 图表线条和柱子要从上一镜的物体长出来。
- **常见坑**：图表默认样式；没有参照物；单位混乱。
- **参考**：assets/template.html、gdgtify-393073

## 9. 3D 产品 / 场景 / 尺度穿越

- **缺省规格**：1920×1080 或 1080×1080，10–40s，Three.js（锁定版本，内嵌或本地文件）。
- **结构**：一条连续运镜贯穿全片。全片只用 2–3 种运镜，每种对应一个叙事目的。
- **关键规则**：
  - **镜头**：
    - 每个场景一个缓动运镜，不连着推了又拉，运动不反向。
    - 尺度穿越时缩放在对数空间里插值。
    - 俯仰角保持在 35–55°。
    - 正俯视时不要精确放在正上方，否则相机朝向会突然转 90°。
  - **布光**：按产品棚拍来：一侧柔光主光，背后加轮廓光。光也可以讲故事，比如从冷到暖。
  - **标签**：用 HTML 覆盖层，每帧从 3D 坐标投影过来。
  - **颜色**：色调映射会让品牌色偏移，要采样渲染出的像素去校正。
  - **质感**：物体要落地，不要悬空零件。
- **常见坑**：
  - 镜头乱飞。
  - 状态泄漏，比如灯光取决于"从哪个房间走进来"。
  - 无头渲染时 WebGL 不可用（加 `--gl swiftshader`）。
  - 输出发虚，原因是像素比没设到输出尺寸。
- **参考**：everestchris6-399895、tanabe-fragm-322001、agioyaz-986461、xanares-738984、alexalbert-274839

## 10. 游戏 / 像素演出，以及把互动页做成视频

- **缺省规格**：1080×1920，3–8s 一段演出，Canvas。
- **演出结构**：
  - 蓄力：抖动和光芒逐渐增强。
  - 爆发：闪白不超过 0.8 不透明度，配冲击波。
  - 奖励：物品弹出并定格。
  - 余韵：光尘缓慢消散。
- **像素风规则**：
  - 先画在低分辨率离屏画布上（如 128×96），再整数倍放大，关闭平滑。
  - 坐标取整；使用固定色板；不用渐变和模糊阴影。
  - 姿态可以平滑插值，但每帧量化到网格上，看起来像 8–12fps 的手绘动画。
- **打击感**：碰撞时物理、粒子、音效、镜头、分数弹出同时发生；震屏要分档。
- **把互动页做成视频**，必须加三样东西：
  1. **自动演示模式**：让 AI 接管玩家输入。如果玩家和 AI 共用同一套操控接口，改起来几乎零成本。
  2. **固定随机种子**：地形、粒子、AI 决策全部改用种子随机。
  3. **固定步长物理加 seek(t)**：从 0 开始按固定步长推进到 t。也可以先预计算整段轨迹存成数组，seek 时直接查表。
- **常见坑**：要求一个单文件里做出联机、语音、可破坏环境；没有 MVP 范围和验收标准。
- **参考**：op7418-814408、zacxbt-944604、godsboy7777-150194、twoclipping-041659

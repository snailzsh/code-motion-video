# 导演稿（brief）

合集里效果好的 prompt 有一个共同点：写代码之前，已经把"做什么"定到可以验收的程度。下面的模板把几十条最完整的 prompt 的结构合并成了一份。先填好写进项目目录的 `brief.md`，再动手。

## 目录
1. 模板
2. 每部分写到什么粒度
3. 低效写法 → 改法
4. 示例：把一句话需求扩写成导演稿

---

## 1. 模板

```markdown
# 导演稿：<片名>

## 0. 目的
看完的人记住什么 / 感受到什么（一句话）：
受众与发布平台：

## 1. 一句话视觉主意
全片唯一的视觉规则。例：一根柱子每折一次长高一倍；所有转场都由同一个圆完成。

## 2. 规格
画幅 1080×1920 · 30fps · 时长 12.0s · 单文件 HTML · 技术：DOM + SVG
循环：否 · 安全区：竖屏上 160px、下 400px、右 140px 不放关键信息；方形和横屏四边各留 5%

## 3. 素材与事实源
- 品牌名 / Logo / 截图 / 配音 / 音乐：<文件路径，没有就写"无，用代码画">
- 事实来源：<网址或文档>。不编造功能、数字、客户名、引语。

## 4. 锁定文案（逐字、按顺序、不加词）
1.
2.

## 5. 分镜表
| 时间 | 画面 | 文字 | 动作 / 缓动 | 怎么接下一镜 |
|---|---|---|---|---|
| 0.0–2.2 | | | | |

有配音时改成按句建行，时间来自 cues.json：
| # | 时间（cue） | 原句 | 画面动作 | 关键词 | 怎么接下一句 |
|---|---|---|---|---|---|
| 1 | 0.30–2.70 | | | | |

## 6. 视觉系统
底色 #______ · 主文字 #______ · 辅助 #______ · 强调色 #______（只给英雄物）
字体：标题 ____ 900 / 正文 ____ 500；数字用等宽数字
字号（以 1080 宽计）：关键词 ≥ 120px，字幕 48–56px，注释 ≥ 24px
版心：左右各 90px

## 7. 动效参数
入场 outExpo 0.5–0.8s；弹簧用临界阻尼（ω≈16，不过冲）；
同组元素错开 2–4 帧；高潮前静止 0.3–0.5s；结尾静止 1.0s

## 8. 禁止清单
交叉溶解、无动机的硬切、装饰性粒子、光晕、镜头光斑、RGB 分离、霓虹渐变、
机器人和大脑之类的 AI 陈词、角落里的假 HUD 数字、超过一个强调色

## 9. 验收
- [ ] 静音也能看懂
- [ ] 每段文字至少停留 8 个干净帧，正常语速读得完
- [ ] render.mjs --check 通过；总览图里没有截断、重叠
- [ ] 事实逐条核对过
- [ ] 时长准确，结尾静止 1 秒
- [ ] 落版 / 结尾帧不撞脸知名品牌（把它当一个 Logo 看：配色加构图像不像谁）

## 10. 复现命令
（素材准备、build_cues、render 的完整命令，别人照着能重新出片）
```

## 2. 每部分写到什么粒度

**目的**：一句话。写不出来，说明还没想清楚要做什么。

**一句话视觉主意**：这是区分好片子和抽奖片子最大的杠杆。没有它，模型会回落成"功能幻灯片"或"特效大杂烩"。好的视觉主意有三个特征：
- 能用一句话说清；
- 贯穿全片，不只是某一镜；
- 跟内容有关，比如"翻倍"就让东西真的翻倍长高。

**规格**：写数字，不写"高清"。画幅、帧率、精确时长、是否循环、平台安全区。

**事实源**：讲产品就给官网、文档或截图；讲历史就给出处。写明"不编造"。拿不准的数字宁可不上屏。

**锁定文案**：逐字写出。要求"不追加口号、不改写"，否则模型会自作主张加 tagline。中文竖屏每行不超过约 16 个字。

**分镜表**：
- 每 0.5–2 秒一格。15 秒大约 4 个视觉主意，一镜一个。
- 每格写清楚：画面里哪个物体在做什么、出现什么字、用什么缓动、怎么离场。
- "怎么接下一镜"这一栏最重要。下一镜应该从上一镜的某个物体长出来，比如曲线变成票据边、数字变成金额。
- 注明"这是起点，不是死模板"，给实现留余地。

**视觉系统**：
- 颜色写 hex，并标明角色（强调色只给英雄物，绿色只表示正向）。
- 字体写到字重和字号；边距写到 px。

**动效参数**：缓动曲线、弹簧阻尼、停留秒数、错峰帧数，都用数字写。

**禁止清单**：具体到效果名。"不要太花"没用，"不要粒子、光晕、镜头光斑"有用。

**验收**：能逐条打勾的才算验收项。

## 3. 低效写法 → 改法

| 低效写法 | 问题 | 改成 |
|---|---|---|
| "做一个 15 秒炫技视频，go all out" | 没概念、没事实，模型回落到通用模板 | 先定一个视觉主意，再定 3 个升级节点 |
| "惊艳""Apple 级""别做成 slop" | 不可执行 | 写 hex、字号、缓动、停留秒数 |
| "展示所有功能、节奏要快" | 和"一镜一意"冲突，必然变成功能幻灯片 | 只选 1 个核心动作 + 2–3 个能力 |
| 风格清单：光晕 + 粒子 + HUD + 神经网络 | 恰好是好片子禁止的东西 | 写禁止清单，强调色只留一个 |
| "从网上找素材" | 截图平移，甚至找错品牌 | 给事实源和素材，或者用代码画 |
| 一句话塞进 3 分钟世界观 | 没有分镜，无法控制 | 拆成分镜表，先做 15 秒 |
| "做个 Tron 游戏""复刻某游戏" | 只有 IP 名，没有规格 | 写清玩家幻想、核心循环、MVP 范围、验收 |
| 不写交付和验收 | 代码能跑就算完工 | 写验收清单和交付清单 |
| 返修时说"不专业""有点颠" | 无法定位问题 | "第 3 秒标题和字幕重叠，标题上移 80px" |

## 4. 示例：把一句话需求扩写成导演稿

**用户原话**："给我的记账 App 做个 15 秒发布视频，要炫。"

**先问（用户在场时最多问三个）**：
1. App 名字和一句话卖点是什么？
2. 有没有截图或品牌色？
3. 发在哪个平台？

用户不在场，就按缺省值继续，交付时说明做了哪些假设。

**扩写后的关键部分**：
- **目的**：让人记住"拍一下小票就记好账"。
- **视觉主意**：一张小票从头到尾不切断。它被折叠、被识别，最后变成账本里的一行。
- **规格**：1080×1080、30fps、15.0s、DOM + SVG、不循环。
- **分镜**：
  - 0–3s：小票从顶部落下，纸边抖一下后落定。
  - 3–6s：一道扫描线扫过小票，金额数字亮起。
  - 6–10s：小票折叠，缩成一行账目，滑进列表；列表里的三类账目依次出现。
  - 10–13s：本月总额数字滚动后落定，曲线画出。
  - 13–15s：Logo 和卖点落版，静止 1 秒。
- **禁止**：手机外壳样机旋转、粒子、光晕、虚构的用户数。

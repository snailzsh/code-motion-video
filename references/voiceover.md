# 配音驱动的片子（讲史、科普、口播配画面）

画面跟着话走，是这类片子成立的前提。做法是：**先有配音，后有动画；时间轴来自配音，不来自拍子。**

## 1. 流程

1. **定稿**：一行一句，每句不超过约 25 字。长句拆开，因为一句话对应一个视觉事件。
2. **逐句合成配音**：每句一个文件，按 001、002… 命名。用什么 TTS 都行，克隆音色也行。逐句合成的好处是：某句不满意，只重配这一句。
3. **拼轨并生成时间轴**（`$SKILL` 指本 skill 目录）：
   ```
   python3 $SKILL/scripts/build_cues.py --lines script.txt --clips clips/ --out-audio voice.wav --out-cues cues.json
   ```
   拼好的音轨会自动标准化到 -14 LUFS（`--lufs 0` 关闭）。
4. **按句写分镜表**：时间码 | 原句 | 画面动作 | 关键词 | 转场。
5. **出静帧**：每句的定格状态各出一张静帧，检查文字截断、句画是否对应。
6. **渲染出片**：
   ```
   node $SKILL/scripts/render.mjs page.html -o out.mp4 --audio voice.wav
   ```

## 2. 拿到每句的时间

**首选：逐句音频 + build_cues.py。** 它会量每句的真实时长，按顺序拼起来：
- 句间停顿用 `--gap`（默认 0.3 秒）；个别句子后面要停久一点，用 `--gap-after 3:0.8,5:1.2`（句号从 1 数）。
- 片头留白用 `--lead`，结尾留白用 `--tail`（默认 1 秒，给收尾定格）。
- 台词行尾写 `｜关键词` 会存进 cue 的 `key` 字段，用来放大字。
- 拼好的音轨默认标准化到 -14 LUFS。

**只有一整条音频时**有两种办法：
- 用 TTS 返回的字级或句级时间戳（很多 TTS 接口提供），直接整理成同样格式的 cues.json。
- 用语音识别做强制对齐，比如 faster-whisper 或 whisper-timestamped 开启词级时间戳，再按标点合并成句。

cues.json 的格式：
```json
{ "duration": 11.5, "cues": [ { "i": 0, "start": 0.3, "end": 1.9, "text": "一张纸，大约 0.1 毫米厚。", "key": "" } ] }
```

## 3. 接进模板

把 `cues` 数组整段替换模板里的 `CUES`，把 `duration` 填进 `CONFIG.duration`。所有动作都写成"第几句开始"，不要写死秒数：

```js
const at = i => CUES[i].start;          // 第 i 句开始的时刻
const until = i => CUES[i].end;
// 第 2 句开始时，柱子开始长高，0.6 秒到位
const p = ease.outExpo(prog(t, at(1), at(1) + 0.6));
```

这样换一版配音，只要重新生成 cues.json，动画会自动对齐。

## 4. 时间规则

- **视觉事件落在句子开始前 0–0.1 秒。** 画面略早于声音，观众会觉得"同步"；晚于声音会觉得拖。
- **转场放在句间停顿里**，不要让一个图形跨过两句话的交界还在变。
- **一句话一个视觉事件。** 一句里塞两个动作，观众只能顾一头。
- **金句之后定格 0.4–0.8 秒**，画面完全静止。用 build_cues 的 `--gap-after` 只加长那一句后面的停顿。
- **字幕与话同进同出**：句子开始时出现，结束时淡出。同一时间只有一句字幕。最后一句不淡出，陪着收尾定格到结束（模板已这样处理）。
- **关键词不要和字幕重复成两遍同样的字。** 字幕是整句，关键词是这句里最重要的 2–6 个字，放大放在画面中上部。
- **没标关键词的句子**：不要硬造关键词，也不要让关键词区空着。把画面主体（地图、线稿）放大到这块，或者把常驻 HUD（如年份）放大进来。

## 5. 竖屏版式（1080×1920）

- **平台界面区**（统一按这组数）：顶部 160px 是状态栏和标题；底部 400px（y > 1520）会被文案、按钮和进度条遮挡；右侧 140px 有点赞、评论按钮。关键信息放在这三块以外，底部 400px 只放可以被挡住的次要信息（比如出处脚注）。
- **字幕区固定**：字幕底边贴着 y ≈ 1510 往上排（模板里是 `bottom: 410px`），折成两行时自动往上长。每集位置不变，观众形成习惯。
- **关键词区**：y ≈ 280–700，字号 ≥ 120px。
- **常驻 HUD** 给观众位置感：讲史放朝代和年份，科普放尺度标尺或步骤进度，按题材选一种即可。竖排的 HUD 放左侧。
- **字幕**：48–56px 粗体，每行不超过约 16 字。超过就让它折成两行，不要拆成两个 cue（一个 cue 对应一个音频文件）。

## 6. 讲史 / 科普的视觉系统

**讲史可以借鉴的元素**：
- 朱印做转场或卷号。
- 竖排朝代名放在左侧（右侧有平台按钮）。
- 年份计数器在年份变化时弹入；每过一年，在线稿上添一笔。
- 势力消长用色块地图表现（色块按 cue 扩张或收缩）。
- 人物用名牌加线稿器物、地点、兵器来表现，**不画真实人物面孔**，既避免失真，也避免争议。
- 纹样、配色随年代演进。

**科普可以借鉴的元素**：
- 一镜一个关键词配一幅线稿。
- 隐喻用画面里本来就有的元素表现。
- 计数器停在真实值上，尺度标尺全程跟着走。
- 片尾给出算式或出处。

**事实护栏**：年代、数字、引文上屏前逐条核对；引文与原文一致；拿不准的写"约"或不上屏。

**做系列时**，先做组件库：片头、HUD、字幕条、地图、人名牌、转场印章。之后每集只换台词、cues 和分镜。

## 7. 混音与响度

配音加背景乐，乐声在人声下自动让位，整体响度标准化到 -14 LUFS：

```
ffmpeg -i voice.wav -i music.mp3 -filter_complex "[0:a]aformat=channel_layouts=stereo,asplit=2[v][sc];[1:a]volume=0.35[m];[m][sc]sidechaincompress=threshold=0.03:ratio=8:attack=20:release=400[duck];[v][duck]amix=inputs=2:duration=first:normalize=0,loudnorm=I=-14:TP=-1.5:LRA=11[out]" -map "[out]" -ar 48000 mix.wav
```

然后渲染时用 `--audio mix.wav`。

**只有人声**：build_cues.py 已经标准化过，直接用。别的来源的人声，单独标准化：

```
ffmpeg -i voice_raw.wav -af loudnorm=I=-14:TP=-1.5:LRA=11 -ar 48000 voice.wav
```

**只有几记音效的短片头**：音效稀疏时积分响度天然偏低，不必硬推到 -14 LUFS，把峰值拉到 -1 dB 左右即可。先量峰值，再按差值加增益：

```
ffmpeg -i sfx.wav -af volumedetect -f null - 2>&1 | grep max_volume    # 例如得到 max_volume: -9.0 dB
ffmpeg -i sfx.wav -af volume=8dB sfx_norm.wav                           # -9 + 8 = -1 dB
```

测响度：

```
ffmpeg -i out.mp4 -af ebur128 -f null - 2>&1 | grep -A2 "Integrated loudness"
```
